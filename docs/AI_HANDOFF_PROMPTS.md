# AI 接手与设计提示词

复制下面适用的提示词给新 AI。文档不是当前实现的保证，新 AI 必须重新核实源码及 STATUS.md。不同工具如果无法访问 E: 盘，应先取得这个工程及 docs，不应虚构读过文件。

## 1. 完整接手提示词

```text
请接手 E:/project/nuxt-content-platform 的 Nuxt 全栈脱敏改造。

首先依次读取 docs/STATUS.md、docs/IMPLEMENTATION_PLAN.md、docs/AI_HANDOFF_PROMPTS.md，并检查适用 AGENTS.md 与当前 Git 状态。以实际文件和最新用户要求为准，计划项不能当成已完成项。

项目根目录下两个独立子项目：nuxt-content-platform-web（现有 Nuxt 前端）与 nuxt-content-platform-backend（Node.js 后端）。共用一个根仓库，不改成 apps/web、apps/api，不给两个子项目分别初始化 Git。

目标是可公开展示的多语言资讯与数据平台。保留原前端技术价值，完成脱敏、必要清理、真实后端及内容发布闭环。后端方向为 TypeScript + Express + Prisma + MySQL，具体版本在实施前核实。不要为展示而引入微服务或过度重写。

原项目 E:/project/nuxt-mobile-marksix 只读参考。不要修改其他项目，不重复复制覆盖现有副本，不连接原公司接口或数据库，不运行旧生产部署脚本，不复制旧 Git 历史。不要输出或写入文档任何真实密钥。公网发布、远程推送须有对应授权。

用户面向广州求职，已有多年实际前端经验。在职阶段独立完成前端并联调后端，个人全栈扩展在离职后完成，履历和文档按事实表述。用户是聋人，使用中文文字沟通；说明应简洁，代码导览和短问答要便于文字面试使用。

当前只做前端逐页脱敏，暂用本地 Mock。只执行用户指定的一页或 STATUS.md 的下一个单项任务，完成后停止，不自动连续改其他页面；后端、数据库、管理端、发布流程暂缓。阅读后续专项提示词不代表执行它们。

按 STATUS.md 的下一步推进，先审查再修改。无用代码需有引用/行为依据；兼容逻辑先核实用途；不要机械删注释或大范围格式化。执行构建前审查脚本外部请求及副作用。每完成一个小阶段执行对应验证；如失败，区分遗留问题与新问题。

结束前必须更新 STATUS.md：修改文件、验证命令及结果、未验证项、设计决定、下一步。最终回复给出结果、文件链接与限制，不能把尚未测试的功能称为可用。涉及关键取舍时同步维护架构说明和面试问答。

现在从当前阶段的第一个未完成任务开始执行，不重新讨论已经确定的目录和技术方向；仅对影响实现且无法从源码判断的信息提问，其余独立工作继续推进。
```

验证本页正常、加载、空数据、失败及非法参数状态（按实际场景适用），检查跳转、多语言、移动端和无原公司请求；无法在当前环境验证的内容如实列出。目标页未脱敏时只验证链接，不宣称链路已完成。

下面路径均相对 nuxt-content-platform-web。选一项复制到上面的【本次页面】位置。统计页面按模块拆开，避免一次改动过大。
