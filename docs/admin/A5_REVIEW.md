# A3～A5 管理端复盘

日期：2026-09-22。复盘范围：管理端 BFF、登录与会话守卫、文章管理读写接口、文章列表和共用编辑弹窗。

## 结论

A3～A5 主链路分层清楚，能够作为作品继续扩展：浏览器只访问同源 BFF，Cookie 会话不进入 JavaScript；管理 API 有固定白名单；文章列表具备筛选、分页和稳定状态；新增/编辑复用弹窗；版本冲突保留用户输入。typecheck、lint、build 和后端集成测试记录完整。

## 已直接清理

- H3 已弃用的 `getMethod(event)` 改为 `event.method`，不继续依赖废弃 API。
- 登录后的 `redirect` 只接受单斜杠开头的站内路径，拒绝 `//host` 形式，收紧跳转边界。

## 视觉与交互复盘

### 做得合理

- 登录错误使用表单内 `n-alert`，不会像短暂 message 一样消失，用户可阅读后修正。
- 列表加载失败使用页面内错误条并提供“重试”；加载、空数据、错误三种状态有区分。
- 弹窗把普通错误、版本冲突、详情加载错误分开；409 冲突提供“重新加载”，没有自动覆盖用户输入。
- 保存成功使用短 message，失败主体保留在对应页面/弹窗内，方向正确。
- 表格设置横向滚动，弹窗限制宽度和内容高度，三语内容不会无限撑高页面。

## 代码与契约复盘

- Route → Controller → Service → Prisma 已用于管理文章接口；草稿不会进入公开查询。
- BFF 只允许固定方法、路径和 query，并明确不转发 Authorization，适合当前单站后台 Cookie 会话。
- `Article.version` 乐观锁覆盖编辑保存；新增删除接口也必须携带 version。
- 当前契约明确“不提供删除”和“不提供上传”，因此新需求必须先更新 ADMIN_CONTRACT、admin-openapi 和 BFF 白名单，再实现，不能只补两个前端按钮。
- 删除采用受限硬删除：只允许 `DRAFT`、`ARCHIVED`，`PUBLISHED` 必须先下线，避免线上内容仍可见而数据库记录已消失。
- 封面上传不能直接写进管理端或 Git 仓库。生产使用对象存储，浏览器仍经同源 BFF；本地开发允许独立本地存储适配器。公开 URL 必须来自配置的可信媒体域名。
